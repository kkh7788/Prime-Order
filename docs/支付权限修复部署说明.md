# 支付入口与管理员权限修复

本次完成本地代码修复，不代表已部署或已通过真实收款验收。

## 改动

- 禁止客户端通过 PAY_ORDER 将订单标记为已付款。
- 创建订单与钱包函数只使用微信平台提供的 OPENID，不再接受 _testOpenid。
- 四个网页后台云函数通过 CloudBase Node SDK 的 auth().getUserInfo() 读取平台确认的调用者 UID，再查询 vibe_admins.web_uid。忽略请求体中的 token、UID 等身份声明；身份缺失或验证出错时拒绝访问。
- 网页不再把 access_token 复制到业务参数，仍通过已登录 CloudBase SDK 调用云函数，由 SDK 的认证传输携带凭证。
- 将 vibe_web_stats 加入部署清单。

## 部署顺序

1. 将下列七个云函数分别上传并部署，选择云端安装依赖。网页云函数目录新增的 admin-auth.js 必须一起上传：
   - vibe_manage_order
   - vibe_createOrder
   - vibe_wallet
   - vibe_web_catalog
   - vibe_web_orders
   - vibe_web_shipping
   - vibe_web_stats
2. 后台四个云函数部署成功后再更新网页：本地开发刷新页面；正式后台重新构建和上传。
3. 小程序重新编译并用自己的微信真机登录测试。控制台中只传 _testOpenid 的模拟调用现在会被拒绝，这是预期行为。
4. 使用绑定在 vibe_admins.web_uid 的真实管理员登录后台，检查商品、订单、运费和看板。普通登录用户应被拒绝。如果管理员也收到 FORBIDDEN，检查 SDK 认证传输和平台调用者 UID 是否与数据库绑定一致；不要恢复请求体 token 解码作为回退。
5. 检查订单创建、未付款订单继续付款的初始化路径及超时拒付。本次测试使用模拟数据，不调用微信支付、不修改云端订单。

本次不需要执行新的 SQL，也不修改已有管理员名单。云函数部署不会替你完成云端权限规则检查；应确保数据库写入和支付回调仅向适当的调用者开放。
